## [1.8.0] - 2026-08-15

> The core file quadrupled in six weeks — 10.7KB at 1.0.0, 40.9KB at 1.7.0 — not because there are four times the obligations, but because every rule arrived carrying its own documentation: mechanism essays, tool caveats, field data. Meanwhile five guides from the 1.0.0 era still held seven lines each, three sentences for the hardest interaction pattern in the APG. This release is the architecture doing what it always claimed: **the core carries obligation, the guides carry depth.** The core loses 10% with zero obligations removed; the thinnest guides grow twentyfold; and a new linter check makes the placement rule permanent — not a content cap (no obligation is ever refused for size — a ceiling on rules would read as a ceiling on accessibility, and it is neither), but a rule about *address*: rationale lives one hop away, in the guide the rule already points at, loaded exactly when the lazy-loading map says so.

### Changed — the core diet (−10.5%, zero obligations removed)
- **Ten rules and anti-patterns compressed to obligation + trigger + one-line mechanism + pointer**, their rationale landed in the guides that already owned the subject: *Independent Verification* rationale and evidence → new **`guide-governance.md` §1.2** (the three levels explained, the Iwashita case, the Greptile numbers, and why a trust-based declaration is still not theater); *Orphaned ARIA Reference* mechanism and field credit → `guide-framework-mapping.md` (which already held the `useId()` trap); *Content Held Hostage by JavaScript* depth → the rewritten `guide-loading-skeleton.md`; *Text over Video*, *Focus Traps Nobody Asked For*, *Image/Media Evidence*, *Cognitive Load*, *Label in Name*, *ARIA Soup*, *Lazy Context Loading* trimmed against depth their guides already carry.
- **Section 7 checkpoints deduplicated against `templates/REPORT.md`** — the checklist names the obligation, the template (lifecycle context, loaded at the delivery event) carries the full instrument.
- Core: EN 40.9 → 36.6KB, pt-BR 43.1 → 38.7KB. Every §2/§3/§6 rule now under 900 bytes in both languages.

### Added — the floor of the library raised (the five 7-line guides, rewritten to house shape)
- **`guide-drag-drop.md`** — *dragging is a shortcut, never the mechanism*: SC 2.5.7 requires a single-pointer alternative for every drag, keyboard requires one more path. The grab/move/drop/cancel keyboard model, the three announcements (grabbed · moved · dropped), drop targets that don't speak in color, and the file-drop zone as the same rule in disguise.
- **`guide-carousels-sliders.md`** — *auto-advance is the accessibility problem; everything else is a labelled group of slides*: pause first in the tab order, rotation stops when focus enters, the slide under focus never leaves the user, `inert` for off-screen slides, and auto-rotation never announced.
- **`guide-infinite-scroll.md`** — *"Load more" is the accessible default; infinite scroll is the exception that has to earn it*: the fleeing footer as a Principle Zero failure, focus onto newly loaded content, batch announcements with position, recoverable Back-button state, `role="feed"`.
- **`guide-loading-skeleton.md`** — *a loading state is a promise, not content*: one status in, one status out, skeletons as `aria-hidden` scenery — plus the JS-gated content section absorbing the §6 anti-pattern's depth (pre-paint `no-js` class, scroll-reveal as the same trap, why `<noscript>` fixes none of it).
- **`guide-toasts-notifications.md`** — *a toast the user cannot perceive, reach, or outlive was never sent*: status vs alert, no focus stealing, nothing actionable on a timer (SC 2.2.1), the action duplicated somewhere permanent, repeats collapsed.

### Added — the guard
- **`placement` check in `lint-standard.py`:** fails any core rule past 900 bytes of body, in either language, with the message pointing at guide-governance §0 — *keep the obligation, move the rationale*. Explicitly a placement rule, not a content cap. Fixture: run against the `v1.7.0` tag, it reports the five rules whose diet produced it.

### Added — Custom Actions (the last item of the v1.2 native queue)
- **Custom Actions in `guide-platform-native.md`** — an action that exists only as a gesture (swipe-to-archive, long-press menu, drag) does not exist for assistive technology: the gesture is intercepted by the screen reader or physically unavailable to switch and voice users. New translation-table row and rules section: every gesture-only action MUST also be exposed as a custom accessibility action (`accessibilityCustomActions` / SwiftUI `accessibilityAction(named:)` · Compose `customActions` · RN `accessibilityActions` · Flutter `CustomSemanticsAction`), with the no-duplication warning (clear child semantics when hoisting) and the supplement-never-hiding-place rule. Native sibling of SC 2.5.1 / 2.5.7. Plus a **Gesture parity** checkpoint in the guide's verification list, naming how the actions surface (VoiceOver "actions available" → one-finger vertical swipe; TalkBack local actions menu) so the human validator knows what to test.

## [1.7.0] - 2026-08-15

> Two fronts in one cycle. **The first is who signs the evidence.** The standard already required the agent to produce the evidence of its own work (*Release Evidence*, 1.2.0), but never said who may sign it — so the answer was, in practice, whoever wrote the code. 1.6.0 had already shown what that costs: the `aria-controls` pointing at a non-existent id survived the generating agent, axe **and** Lighthouse, and surfaced only in a test someone else ran. The same conclusion is arriving from outside accessibility — models find more bugs in code written by another model than in their own (Greptile, [*Models are worse at reviewing their own code*](https://www.greptile.com/blog/model-inversion), 2026-07-21: two 500-PR datasets, one authored by Claude Code and one by Codex, ~1,500 ground-truth comments; GPT reached 62% recall on Claude-authored PRs against Claude's 53.7% on its own, with the inverse pattern on Codex code). With that rule come three defects from the same family: things a clean automated run does not see. Two of the three came from this project's own landing page, built under this standard — one because the axe rule that catches it ships disabled, one because no checker can see it at all, and one because the two tools this standard recommends contradict each other.
>
> **The second front is the components the standard named and never covered.** An audit of its own text found four of them: *Visual Patterns* (§3) has required charts to survive without color since 1.0.0 and no guide ever explained how; §5 offered "Charts, Dynamic Grids" as its example of an *unmapped* component while §2.1 quietly routed charts to the color guide; §6 told the agent not to reinvent Datepickers and TreeViews without saying what a correct one does. Maps were not named anywhere — the one component where the whole task can be locked behind a canvas. And a fifth guide covers what this project is closest to and had never addressed: the interface that *is* the model. Five guides, 24 → 29.

### Added — Independent verification
- **Independent Verification (AI Behavior Contract — rule 18):** the agent that generated the interface MUST NOT be the sole author of the evidence that it conforms. Before a `REPORT.md` can carry ✅ PASS, the Section 7 checkpoints that do not require a human must be reproduced by a verifier that did not write the code, and the report must declare the level reached: **cross-agent** (a different model audits it), **fresh-context** (same model, new session, without the conversation that produced the code — what is removed is the memory of having decided), or **self-reported** (permitted, marked ⚠️, and capped at CONDITIONAL). Where no second agent is available — an integrated vibe-coding tool, a single-session IDE — **fresh-context is the floor**, and it costs a new chat, not a new tool. The rule does not move the human out of the loop: it removes the *generator* from the position of sole witness of the mechanical part. Every human checkpoint stays mandatory at every level — a second agent can resolve a reference across two files, it cannot hear a screen reader.
- **Verification Independence field in `templates/REPORT.md`,** with the level and who reproduced the checkpoints, plus an **Independent Verification** checkpoint closing the Verification Workflow (Section 7).
- **`independence` check in `verify-a11y.py`:** fails a report with no level declared, with more than one declared (an untouched template menu), or claiming PASS while self-reported; warns when the level is declared but nobody is named. Read from the field alone, never from the whole document — the template's own explanation of the field names all three levels, which is the trap the status check fell into before 1.5.0.
- **Label in Name (SC 2.5.3, Operable):** the accessible name of a control MUST contain its visible text, in the same order. Voice-control users say what they read, so an `aria-label` that *replaces* the visible text makes the control unreachable by voice. The criterion was cited only in passing inside *ARIA Soup*, in a standard that declares WCAG 2.2 AA on its cover.
- **Content Held Hostage by JavaScript (anti-pattern, Section 6):** entry animations written as `opacity: 0` in CSS and made visible by script render the page **empty** when the script fails, is blocked, or has not run yet — with the content in the DOM and invisible to everyone. No automated checker catches it, because in the checker's browser the script ran. Under Principle Zero that is a broken feature, not a degraded experience.
- **Focus Traps Nobody Asked For (anti-pattern, Section 6):** `tabindex="0"` on scroll containers that do not scroll. The axe rule `scrollable-region-focusable` is **conditional**, and applying it unconditionally litters the tab order with stops that lead nowhere.

### Added — Five guides for components the standard already named
- **`guide-charts.md` — Charts & Data Visualization:** the rule the standard was missing — **a chart is data drawn, so its text alternative is the data**, not a description of the drawing. An `alt` reading "bar chart showing revenue growth" passes every checker and carries no number at all; informative charts ship an equivalent table or dataset, at every profile. Plus the three shapes that decide the whole technique (static image · inline SVG with `role="img"` and hidden children · interactive), keyboard navigation *between data points* rather than a tab stop per point, why `aria-live` on a redrawing chart reads the redraw instead of the result, and why canvas has no accessibility tree at all.
- **`guide-datepicker.md` — Date Picker & Calendar:** **the typed input is the feature and the calendar is an affordance on top of it** — a picker that removes the text field is the most common way a date field becomes unusable, and blocking paste on it fails SC 3.3.8 for the same reason it fails on a password. Plus the APG grid model (one tab stop, arrows inside, full date in every cell label), announcing the month change nobody announces, ranges, `aria-disabled` instead of removal for unavailable dates, and when `<input type="date">` is simply the better answer.
- **`guide-treeview.md` — Tree View & Hierarchy:** opens by asking whether it should be a tree at all — most generated trees are navigation menus wearing `role="tree"`, and the role makes them *worse* by suppressing the user's normal reading commands. Then the real pattern: roving focus, `aria-expanded` only where there are children, `aria-level`/`aria-setsize`/`aria-posinset` whenever the DOM is not the whole tree, and expansion as a state independent from selection.
- **`guide-maps.md` — Interactive Maps:** the clearest Principle Zero case in the library — **if the task can only be completed on the map, the task cannot be completed.** The list beside the map is not a fallback, it is the primary path; nothing may require dragging a pin. Plus keyboard pan/zoom, markers as named controls, `role="application"` as a loaded gun, gesture alternatives (SC 2.5.1), and third-party providers, where the obligation does not transfer with the embed.
- **`guide-generative-ui.md` — Generative & Conversational Interfaces:** the standard exists because AI writes interfaces; this covers the case where the interface **is** the AI. **Streaming output and live regions are natural enemies** — a response arriving token by token inside `aria-live` makes the screen reader stutter or restart, and the markup is textbook-correct, so nothing flags it. Announce the transitions, render the content. Plus the conversation as `role="log"`, *Stop generating* as an SC 2.2.2 requirement, never stealing focus, distinct accessible names for per-message actions, and **UI a model assembles at runtime — markup no code review ever sees**, which is *Independent Verification* one layer down.
- **§2.1 loading triggers for all five**, plus the row that hid the gap: "chart, dashboard" used to point at the color guide, so an agent building a chart got contrast advice and never learned it owed a data table. Charts and images no longer overlap on the same keyword either.

### Added — Assistive technologies beyond the screen reader
- **Beyond the Screen Reader checkpoint (Section 7)** and a **Voice Control** entry in `templates/REPORT.md`: every visible control activated by **speaking its visible label**, validated with the platform's voice control or by reading each accessible name against its label. *Label in Name* arrived in this same release with no way to verify it — the criterion exists for voice-control users, and every verification point in the standard, from 1.0.0 to here, asked only for a screen reader. Obligation without a trigger, one more time.
- **Assistive technologies beyond the screen reader** in `guide-platform-native.md`: Voice Control / Voice Access, Switch Control / Switch Access and Full Keyboard Access named in the native verification checklist. All three consume the same accessible name and focus order the screen reader does, which is why a control named only for the screen reader breaks four technologies at once.

### Added — Tooling and governance
- **`guide-governance.md` §1.1 — Default configuration is not coverage:** how to enable the experimental axe rules that carry a Success Criterion (`label-content-name-mismatch`, SC 2.5.3, ships **disabled**), and how to resolve the `eslint-plugin-jsx-a11y` × axe conflict on `no-noninteractive-tabindex` by configuring `roles: ["region"]` instead of disabling the rule — the path of least resistance, which removes a real guard. Plus: a CI gate is itself a form of independent verification for the mechanical layer, and none at all for the human one.

### Changed
- **Technical Check (Section 7)** now states that a clean run means "no violation among the rules that were enabled", pointing at the two default gaps above.
- **Complex Component Protocol (Section 5)** no longer offers "Charts, Dynamic Grids" as its example of an unmapped component — both are mapped now. It triggers on the real condition: no row in the §2.1 map and no equivalent in the APG.
- **Reinventing the Complex Wheel (Section 6)** links TreeViews, Datepickers and Charts to their guides, and states what adopting a library still leaves open: the pattern, never the Definition of Done.
- **Visual Patterns (Section 3)** now carries the data-equivalent rule, so the obligation exists in the normative body and not only in the guide.

### Migration
- A `REPORT.md` written before this release has no *Verification Independence* field, and `verify-a11y.py` now fails on its absence. Add the line from `templates/REPORT.md` and declare the level — `self-reported` is a valid answer, and an honest one; it only caps the status at ⚠️ CONDITIONAL. Teams mid-adoption can keep the gate advisory with `--warn-only`.

## [1.6.0] - 2026-08-13

> Driven by the first independent test anyone ran on this standard: [a11y-md-ai-test](https://github.com/mjepis7/a11y-md-ai-test), by **Maria Eduarda Iwashita**, published in June against a pre-1.0.0 version. An A/B design with a blind baseline session, Claude Opus generating React UI at two levels of complexity, evaluated with axe-core, Lighthouse, keyboard and VoiceOver. Its headline finding is one this project did not have: **the gain scales with component complexity** — near-parity on a simple checkout, five of six keyboard scenarios broken on a complex panel. Its second finding is the one this release turns into a rule: the *guided* version still shipped a critical bug, an `aria-controls` pointing at an id that did not exist, because two components each called `useId()`. Both components were individually correct. The reference between them was not.

### Added
- **Orphaned ARIA Reference anti-pattern (Section 6):** `aria-controls`, `aria-labelledby`, `aria-describedby` and `aria-activedescendant` MUST NOT point at an id absent from the rendered DOM. It is the **inverse** of *ARIA Soup* — there, ARIA is added where native semantics sufficed; here it is syntactically correct and empty at the destination. The common cause sits *between* components, where each side generates its own identifier; when a relationship attribute crosses a component boundary, the id must be generated on one side and passed to the other. Credited to the study above, which is also where the failure mode was observed passing both axe and Lighthouse.
- **"IDs that cross component boundaries"** in `guide-framework-mapping.md`: the `useId()` trap with correct and incorrect code, and the rule that the identifier has a single origin and travels down as a property.
- **`orphaned-aria` check in `verify-a11y.py`:** resolves literal ARIA relationship targets against the ids declared in the same file. Reported as a warning, since the target may legitimately live elsewhere — the dynamic form (`aria-controls={panelId}`) stays a job for human review, which is precisely where this defect hides.
- **`.github/workflows/standard-integrity.yml`:** the repository now runs its own `lint-standard.py` on every pull request and push. The standard requires evidence before delivery and was relying on someone remembering to run the linter — the same phase-trigger failure the 1.2.0 post-mortem documented, applied to itself.
- **This standard's own tools in `guide-governance.md` §1:** the Static Verification section recommended `eslint-plugin-jsx-a11y` and `axe` and never mentioned the two scripts the project publishes, which left them reachable only from a footnote in the README.

## [1.5.0] - 2026-08-10

> Three things arrived in one cycle. First, the question 1.3.0 invited: does a user-supplied *video* need the same treatment as a user-supplied image? The principle transfers — an agent must not classify media it cannot perceive — but six Level A criteria (1.2.1, 1.2.2, 1.2.3, 1.4.2, 2.2.2, 2.3.1) and 1.2.5 at AA appeared nowhere in the standard, while background video, autoplaying loops and scroll-driven parallax became a default of contemporary interfaces. Then scanning an external accessibility library surfaced a gap carried since 1.0.0: the standard declares WCAG 2.2 AA on its cover, and of the six Level A/AA criteria WCAG 2.2 actually added, the three missing ones were **all** the cognitive ones (3.2.6, 3.3.7, 3.3.8). Finally, a full audit run before publishing found something worse than either — the static gate that enforces "no PASS without human validation" had been neutralized by the report template itself. Alt text was a missing sentence; time-based media was a missing chapter; cognition was a missing floor. The pattern from 1.2.0 and 1.3.0 holds a third time: the obligation existed, the trigger did not.

### Added — Time-based media
- **Media Evidence (AI Behavior Contract):** when video or audio enters the interface — supplied by the user, embedded from a third party, or generated as part of the UI — the AI must resolve its accessibility contract **before the media enters the code**, and must not classify it as decorative on its own. Because it cannot perceive a media file, it asks the developer in the same turn: does this carry information or function, does it have audio, do captions/transcript/audio description already exist. Captions and transcripts produced by a machine ship as **drafts for human review** — an unreviewed auto-caption is the `alt` deduced from a filename, in another medium. Unresolved media blocks the Definition of Done (functional without alternative = CRITICAL, informative without captions = HIGH, autoplaying audio without control = CRITICAL).
- **`guide-media.md` — Time-Based Media, Background Video & Motion:** the classification test applied to media, the three questions of Media Evidence, a correct background-video implementation (autoplay granted by script so the reduced-motion preference can veto it before a frame moves), the scrim measurement for text over video, parallax degrading to a static composition, third-party embeds, and the nine Success Criteria mapped.
- **Time-Based Media (SC 1.2.2, 1.2.5)** and **Audio Control (SC 1.4.2)** in Perceivable; **Moving Content (SC 2.2.2)** and **Flashing (SC 2.3.1)** in Operable. Three of the four are Level A — absent at every profile, Launchpad included, where the standard promises to relax the visual without touching the semantic floor.
- **Text over Video anti-pattern (Section 6):** the contrast of a headline over video changes frame by frame and every automated checker passes it — axe measures the text against the container's computed background, which is transparent. The text must sit on a scrim, measured in the composited worst case. Same class of failure as the silent `alt=""`: conformant to every tool, broken for the user.
- **Media & Motion checkpoint** in the Verification Workflow, including one validation pass with `prefers-reduced-motion: reduce` active, and a matching **Section 5 — Time-Based Media and Motion** block in `templates/REPORT.md`, skippable with an explicit "N/A" when the interface carries no media.

### Added — Cognitive accessibility
- **Cognitive Load (AI Behavior Contract):** when generating a multi-step flow, an authentication, or any time limit, the AI must verify three things before shipping — nothing the user must **remember** across screens (SC 3.3.8), nothing they must **type again** within the same process (SC 3.3.7), and help in the **same relative position** across screens (SC 3.2.6). Blocking `paste` on a password field is 🔴 CRITICAL: it reintroduces the memory test the criterion exists to remove, and it is the single most common way generated login code fails.
- **Conflicting Access Needs (AI Behavior Contract):** the first rule for accessibility against *accessibility*. Motion orients people who struggle to track context change and triggers nausea in vestibular disorders; plain language lowers cognitive load and strips precision the expert depends on. Where a user-controlled channel exists (`prefers-reduced-motion`, `prefers-contrast`, an account preference), implementing it is the answer; where none exists, the AI must name both populations, escalate to the developer, and record the choice in `A11Y-DECISIONS.md` with both needs stated. A user majority is not a tie-breaker.
- **`guide-cognitive.md` — Cognitive Accessibility, Language & Conflicting Needs:** the three WCAG 2.2 cognitive criteria with the code that fails them, text spacing (SC 1.4.12), adjustable timing (SC 2.2.1), a plain-language section for generated interface copy, the conflicting-needs protocol, and the W3C's eight objectives as a coverage map.
- **Accessible Authentication (SC 3.3.8), Redundant Entry (SC 3.3.7)** and **Consistent Help (SC 3.2.6)** in Understandable; **Text Spacing (SC 1.4.12)** in Perceivable; **Timing Adjustable (SC 2.2.1)** in Operable. **SC 1.4.13** now cited in the tooltips guide, whose three rules were already the criterion's three conditions, unnamed.
- **Cognitive Load checkpoint** in the Verification Workflow, and a matching **Section 6 — Cognitive Load and Flow** block in `templates/REPORT.md`.

### Added — Discoverability, components and governance
- **§2.1 — Loading Triggers map:** one table mapping task keywords to reference files, plus the three templates with their events. *Lazy Context Loading* forbids preloading the references but never said how the agent maps a task to a filename — an audit of the 24 guides found **18 discoverable only through a domain list at the top of a POUR section**, which is a category, not a trigger. `guide-consent-banners.md` and `guide-content-interaction.md` were the sharpest cases: a cookie banner reads as "modal", and nothing in the name `content-interaction` says microcopy or timeouts. Reachable was never the same as discoverable.
- **`guide-consent-banners.md` — Consent & Cookie Banners:** the modal/non-modal fork that defines everything else, the fixed bottom strip obscuring the focus indicator (SC 2.4.11, a Level AA failure invisible to mouse testing), accept/reject effort parity as a House Rule, and third-party CMPs — where the obligation does not transfer with the script.
- **Nullified Alt anti-pattern (Section 6):** `aria-hidden="true"` on an image carrying a non-empty `alt` — the attribute is present and descriptive, every checker passes, and the screen reader never sees the image. Same class of failure as the silent `alt=""`.
- **Accessibility Overlays anti-pattern (Section 6):** asked to "make this accessible", an unconstrained agent reaches for the cheapest-looking answer. An overlay does not fix the DOM that produced the barrier; it adds a layer that conflicts with the assistive technology the person already configured. Position of the IAAP and the European Disability Forum, and the European Commission records that overlays do not guarantee compliance.
- **Screen reader + browser pair** now recorded in `REPORT.md`, with who ran it and when. The checkpoint asked "did you use VoiceOver/NVDA?" — a reader without a browser is not reproducible evidence (NVDA + Firefox and NVDA + Chrome diverge in ARIA behavior), and JAWS, the most used reader on corporate Windows, appeared nowhere in the standard.
- **Formal evaluation (WCAG-EM)** in the governance guide, as a conditional track: not every product is audited, but `REPORT.md` tracks a *feature* while an audit evaluates a *site* — the gap surfaces when the Accessibility Declaration has to be issued. Includes the five WCAG-EM steps and the W3C's official report tooling.
- **Brazilian compliance (ABNT NBR 17225:2025 / LBI art. 63)** in the governance guide — the standard cited ADA, EAA, EN 301 549 and ISO 9241-171, and nothing from the market its own pt-BR edition serves.
- **`triggers` check in `lint-standard.py`:** every guide and every template must appear in the §2.1 map. `orphans` proved a guide was linked somewhere in the core; this proves something states when to open it. Verified against a fixture where a guide keeps all its old citations and loses only its map row — the old checks pass, this one fails.
- **`wiki` check in `lint-standard.py`:** the Wiki is public documentation living outside version control, so nothing stopped it from drifting. It now must document the same number of contract rules as the core file and list every reference guide. Skipped when the folder is absent.

### Changed
- **Motion (Section 3, Operable):** the rule covered "heavy state animations during crucial transitions" — which is neither autoplay nor parallax, the two motions users actually cannot escape. It now names both, requires the reduced-motion path to be built as the **default** with motion added in the `no-preference` branch, and links the new guide.
- **Component Reuse** now states what reuse does *not* buy: accessible components can be composed inaccessibly — focus order *between* components, heading hierarchy, landmarks and the content filling the component remain the screen's responsibility. Reuse satisfies the rule, never the Definition of Done.
- **`guide-content-interaction.md`** rescoped: its one-line multimedia section (*"audio and video MUST have text alternatives or synchronized captions"*) carried the entire obligation for time-based media. Sensory language stays; media moves to its own guide, with the pointer left in place.
- **`guide-carousels-sliders.md`:** the pause control is now cited as SC 2.2.2 Level A instead of a house recommendation, and off-screen slides now use `inert`. The previous recipe — `aria-hidden="true"` plus `tabindex="-1"` — does not remove the buttons and links *inside* the slide from the tab order, which is precisely the invisible focus the rule exists to prevent.

## [1.3.0] - 2026-08-07

> Driven by a question from the field: how does the standard handle alt text when the *user* supplies the image? The taxonomy existed, the SC 1.1.1 MUST existed — but no rule fired at the moment an image entered the conversation, which is exactly where agents fabricate an `alt` from the filename and move on. Same lesson as 1.2.0: obligation was not the variable — placement and trigger were.

### Added
- **Image Evidence (AI Behavior Contract):** when the user supplies an image — pasted into the conversation or referenced as an asset — the AI must resolve its text alternative before the image enters the code. If it can perceive the image (multimodal input or an image-reading tool in the environment), it classifies it via the removal test and proposes the `alt` **as a draft for the developer to confirm** — the human decision is part of the rule, not a courtesy. If it cannot, it requests the description in the same turn. Fabricating an `alt` from a filename or defaulting to `alt=""` are contract violations; an unresolved image blocks the Definition of Done (functional = CRITICAL, informative = HIGH).
- **`guide-images.md`, Section 5 — user-supplied images:** the three-step flow behind the rule (perceive → classify by the removal test → propose for human confirmation), the failure modes it forbids — including the silent `alt=""` no automated checker can catch — and borderline classifications routed to `A11Y-DECISIONS.md` as pattern-level decisions.

### Changed
- **Alt Text (Section 3, Perceivable):** the line now opens by stating that every `<img>` carries an `alt` attribute and that informative and functional images require a non-empty description; the **empty value** (`alt=""`) is reserved for images a human confirmed as decorative — a decision, never a default. The empty value is always named in prose, never only in notation, so no agent can misread "`alt=""` is for decorative images" as "the `alt` attribute is for decorative images". An `alt` deduced from a filename is fabricated evidence.
- **Wiki — AI Behavioral Contract:** the contract grows to 14 rules; Image Evidence documented with the human-in-the-loop rationale (vision gives the content, only product context gives the purpose — the machine prepares the evidence, the human establishes it).

## [1.2.0] - 2026-08-02

> Driven by a documented field post-mortem: an agent applied the standard to a real project for weeks, generated and maintained `A11Y-DECISIONS.md`, and never produced a `REPORT.md` or an `EXCEPTIONS.md`. The artifact that existed was the only one named inside a rule of the AI Behavior Contract. Obligation was not the variable — placement and trigger were.

### Added
- **Exception Memory (AI Behavior Contract):** accepting a WCAG SC violation now requires creating or updating `EXCEPTIONS.md` **in the same turn**, from the template, with risk owner, approver, tracking issue and expiry. An accepted-but-unrecorded exception is a contract violation, not a pending decision.
- **Release Evidence (AI Behavior Contract):** before any delivery to an end user — build, deploy, shared artifact, tag — the AI must verify a `REPORT.md` newer than the last interface change, or state that the delivery carries no conformance evidence. Event trigger, so it fires in continuous-delivery projects where a "final delivery" phase never arrives.
- **Artifacts Present** checkpoint, now first in the Verification Workflow: the six existing checkpoints verified the interface, none verified that evidence of it exists.
- **Headless-agent clause** (Section 7 and `REPORT.md`): an agent without a browser must still produce the report, marking unverifiable checkpoints and naming who must run them. A partial, honest report is evidence; a missing report is not.
- **Marking legend in `REPORT.md`:** `[x]` verified with evidence · `[!]` verified and failed · `[~]` partial · `[ ]` not verified, reason required. Removes the ambiguity of an empty checkbox and the incentive to mark what "is probably fine".
- **Governance guide, Section 0 — where a rule belongs:** anything the AI must DO belongs in the behavior contract with an explicit event trigger; guides carry depth, never sole obligation.
- **ARIA Soup anti-pattern (Section 6):** named prohibition of decorative/redundant ARIA — no ARIA where native HTML provides the semantics, no redundant roles, no static never-updated ARIA states. Response to the WebAIM Million 2026 finding (133+ ARIA attributes per page, 6× since 2019, with more ARIA correlating with more errors).
- **Benchmark pre-registration (`benchmark/`):** methodology and verbatim prompts for measuring whether A11Y.md reduces automatically detectable violations in AI-generated UI — published before any data collection.

### Changed
- **Lazy Context Loading no longer covers `templates/`:** `references/` is per-component context (load on demand); `templates/` is lifecycle context and must be loaded when its triggering event occurs. Adds **template fidelity** — artifacts are created from the template files, never deduced from prose, resolving upstream first when the folder is absent.
- **"Optional Templates" renamed to "Project Artifacts"** *(versioned, not optional)*, each with its trigger. The index label contradicted a normative body that says MUST four times.
- **`templates/EXCEPTIONS.md`:** every exception now requires a **risk owner**, an **approver**, a **tracking issue** and an **expiry date**, at the narrowest practical scope; in review mode the AI flags expired exceptions as 🟠 HIGH technical debt. An exception is temporary and is never silently suppressed.
