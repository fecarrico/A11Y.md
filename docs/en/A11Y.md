# A11y Guidelines: Accessibility as a Baseline
> **Version:** 1.8.0 | **Target Standard:** WCAG 2.2 AA | **Last Updated:** 2026-08-15

This document establishes the persistent context required so that the software **can be certified** under the **WCAG 2.2 AA**, **ISO 9241-171**, **ADA**, and **EAA** standards, depending on rigorous implementation and **mandatory human validation**.

## 0. Principle Zero: Accessibility as Pre-condition
- Accessibility is not a feature or an incremental improvement; it is a **pre-condition for use**. 
- If a user cannot complete a task due to an accessibility barrier, the feature is considered **technically broken**.
- **Task Completion** success is our primary quality metric.

## 0.1. Compliance Profile
*Reference: [Compliance Profiles Detail](references/guide-compliance-profiles.md)*

This document defaults to **Standard (AA)** compliance.
When generating or reviewing interface code, the AI should ask the user which compliance profile to apply if not already specified:

| Profile | Target | Contrast (text / UI) | Min Font† | Min Target | Use Case |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **🛡️ Shield (AAA)** | WCAG AAA | 7:1 / 3:1 (SC 1.4.6, 1.4.11) | 14px† | 44×44px (SC 2.5.5) · 48×48px† advised | Regulated industries, healthcare, gov |
| **⚖️ Standard (AA)** | WCAG AA | 4.5:1 / 3:1 (SC 1.4.3, 1.4.11) | 12px† | 24×24px (SC 2.5.8) · 44×44px† advised | Default. Production apps, public web |
| **🚀 Launchpad (A)** | WCAG A | 3:1† (house floor) | 10px† | 24×24px† | MVPs, internal tools, prototypes |

*† = **House Rule**, non-normative: this standard's ergonomic policy where WCAG requires less — or nothing — at that level. WCAG defines no minimum font size at any level; Level A defines no contrast or target-size criteria; 44–48px targets come from Apple HIG / Material Design. Skipping a **WCAG SC** at your target level MUST be logged in `EXCEPTIONS.md`; relaxing a **House Rule** is a product decision — record it in `A11Y-DECISIONS.md`.*

*Launchpad additionally requires explicit `EXCEPTIONS.md` documentation for each criterion relaxed below AA.*

> ⚠️ The **Launchpad (A)** profile does NOT relax CRITICAL rules (Section 1). 
> Keyboard operability, focus management, and semantic HTML remain mandatory 
> at ALL levels — these are Level A requirements.

## 1. Severity & Impact Model
Evaluate the impact of any design or implementation decision following these levels:
- 🔴 **CRITICAL:** **Operation** failures. Blocks **Task Completion** or renders the function unusable (e.g., Broken keyboard navigation, Click on Div/Span, Modal without focus management). **MUST FIX.**
- 🟠 **HIGH:** **Perception and Readability** failures. Significantly increases **Error or Abandonment Rate** (e.g., Insufficient contrast, Fonts < 12px in critical text, Lack of Dynamic Feedback). **MUST FIX.**
- 🟡 **MEDIUM:** Reduces **Efficiency and Satisfaction** (e.g., Lack of optional keyboard shortcuts, lack of redundant labels). **SHOULD FIX.**
- 🔵 **LOW:** **Cosmetic or Polish** impact (e.g., Micro-interactions without aria-labels, improvements to Focus Indicators that are already visible). **MAY FIX.**

## 2. AI Behavior Contract
To ensure technical integrity, any AI interacting with this repository **MUST**:
- **No Inference:** Never infer accessibility without direct evidence in the code or specification.
- **Lazy Context Loading:** Reference files (`references/`) **MUST NOT** be preloaded — they are *per-component* context, consulted only when the task involves that component type; **§2.1** states which file matches which task. `A11Y.md` alone is sufficient for most generation tasks. **This does NOT apply to `templates/`:** templates are *lifecycle* context and **MUST** be loaded when their triggering event occurs (a decision made, an exception accepted, a delivery shipped). **Template fidelity:** artifacts **MUST** be created from the files in `templates/`, never deduced from prose. If either folder is unavailable locally, resolve the relative links against the upstream repository *before* creating the artifact: `https://github.com/fecarrico/A11Y.md/tree/main/docs/en/`.
- **Reference APG:** Prioritize patterns from the [WAI-ARIA Authoring Practices Guide (APG)](https://www.w3.org/WAI/ARIA/apg/).
- **Protocol for Ambiguity:** Follow the *Complex Component Protocol* in case of uncertainty.
- **Explain Trade-offs:** Explain impacts on Accessibility vs UX vs Business when suggesting changes.
- **UI Component Interrogation:** Before adding `onClick` to non-semantic elements, the AI **MUST** propose replacing them with native elements or full ARIA patterns.
- **Image Evidence:** When the user supplies an image — pasted or referenced as an asset — the AI **MUST** resolve its text alternative before the image enters the code. If it can perceive the image, it classifies it (the removal test gives the content, the surrounding context gives the purpose) and proposes the `alt` as a **draft for the developer to confirm**; if it cannot, it **MUST** request the description in the same turn. Fabricating an `alt` from a filename or silently defaulting to `alt=""` are contract violations — declaring an image decorative is a human-confirmed decision, never a fallback. An unresolved image blocks the Definition of Done: functional 🔴 · informative 🟠. *Reference: [Images §5](references/guide-images.md)*
- **Media Evidence:** When video or audio enters the interface — supplied, embedded, or generated — the AI **MUST** resolve its accessibility contract **before the media enters the code**, and **MUST NOT** classify it as decorative on its own. It cannot perceive a media file, so it **MUST** ask the developer in the same turn: information or function? audio track? do captions, transcript or audio description exist? Machine-produced captions and transcripts ship as **drafts for human review**, never as the delivered alternative. Decorative status exempts media from captions, never from **Moving Content** or **Audio Control** (Section 3). Unresolved media blocks the Definition of Done: functional without alternative 🔴 · informative without captions 🟠 · autoplaying audio without control 🔴. *Reference: [Time-Based Media & Motion](references/guide-media.md)*
- **Framework Adaptation:** Examples in this document use React/TSX syntax. On **web** frameworks, the AI MUST transpose patterns to the active project's framework while preserving semantic equivalence. *Reference: [Framework Mapping](references/guide-framework-mapping.md)*
- **Platform Awareness:** The AI MUST identify the target platform **before** loading any reference. The normative layer of this document (Principle Zero, POUR, profiles, severity, governance) is platform-agnostic; the technical references are web-first. On native platforms (iOS, Android, React Native, Flutter), web references MUST be read as **semantic intent to translate — never implementation to copy**: no ARIA attributes or CSS pixels outside the web. *Reference: [Platform-Native Mapping](references/guide-platform-native.md)*
- **Cognitive Load:** When generating a **multi-step flow**, an **authentication**, or any **time limit**, the AI **MUST** verify the three cognitive obligations before shipping: nothing the user must **remember** across screens (SC 3.3.8), nothing they must **type again** within the same process (SC 3.3.7), and help in the **same relative position** across screens (SC 3.2.6). Blocking `paste` on a password field is 🔴 CRITICAL — it reintroduces the memory test the criterion exists to remove. *Reference: [Cognitive Accessibility](references/guide-cognitive.md)*
- **Conflicting Access Needs:** When mitigating one accessibility need creates a barrier for another (motion × vestibular disorders, plain language × technical precision, high contrast × brightness sensitivity), the AI **MUST NOT** arbitrate silently. Where a channel exists for the user to decide (`prefers-reduced-motion`, `prefers-contrast`, an account preference), implementing that channel is the answer. Where none exists, the AI **MUST** name both populations, present the options to the developer, and record the choice in `A11Y-DECISIONS.md` with both needs stated. A user majority is not a tie-breaker. *Reference: [Cognitive Accessibility](references/guide-cognitive.md)*
- **Component Reuse:** Before generating any interactive component, the AI MUST check for an existing implementation in the project or its design system and extend it. Generating a parallel implementation of an existing pattern is a violation. **Reuse does not close verification:** accessible components can be composed inaccessibly — focus order *between* components, heading hierarchy, landmarks and the content filling the component remain the screen's responsibility. Reuse satisfies this rule, never the Definition of Done (Section 7).
- **Decision Memory:** Choices between equally conformant alternatives (e.g., `alertdialog` vs `dialog` for a destructive confirmation) MUST be recorded in `A11Y-DECISIONS.md` — indexed by pattern, never by screen — and reused in later turns. *Reference: [Decisions Log](templates/A11Y-DECISIONS.md)*
- **Exception Memory:** When knowingly accepting a violation of a WCAG SC at the target level, the AI **MUST** create or update `EXCEPTIONS.md` **in the same turn**, from `templates/EXCEPTIONS.md`, with risk owner, approver, tracking issue and expiry. An accepted-but-unrecorded exception is a contract violation, not a pending decision. *(Relaxing a House Rule† is a product decision — it belongs in `A11Y-DECISIONS.md`, not here.)*
- **Release Evidence:** Before any delivery to an end user — published build, deploy, shared artifact, tag — the AI **MUST** verify that a `REPORT.md` exists, was generated from `templates/REPORT.md`, and is newer than the last interface change. If it does not exist, the AI **MUST** generate it or state explicitly that the delivery carries no conformance evidence. In continuous-delivery projects this rule is what triggers the report: waiting for a "final delivery" event that never happens is not compliance.
- **Independent Verification:** The agent that generated the interface **MUST NOT** be the sole author of the evidence that it conforms. Before `REPORT.md` can carry ✅ PASS, the Section 7 checkpoints that do not require a human **MUST** be reproduced by a verifier that did not write the code, and the report **MUST** declare the level reached: **cross-agent** (another model or agent audits the code), **fresh-context** (the same model in a new session, without the conversation that produced the code), or **self-reported** ⚠️ (the generating agent — permitted, marked, and capped at CONDITIONAL, never PASS). Fresh-context is the floor: a new chat over the same project, never a new tool. Human validation stays mandatory at every level — a second agent can resolve a reference between files; it cannot hear a screen reader. *Rationale and evidence: [Governance §1.2](references/guide-governance.md)*
- **Mode Awareness:** When generating new code, apply all rules proactively. When reviewing existing code, identify violations, classify by severity (Section 1), and suggest targeted fixes — do not propose full rewrites unless the structural damage is CRITICAL. If an `EXCEPTIONS.md` exists, consult it: an entry there is a legitimate dispensation, but an entry past its expiry date MUST be flagged as 🟠 HIGH technical debt.

## 3. Technical Standards (POUR Framework)

### Perceivable
*References: [Images](references/guide-images.md) | [Time-Based Media & Motion](references/guide-media.md) | [Charts & Data Visualization](references/guide-charts.md) | [Content & Timing](references/guide-content-interaction.md) | [Visual Perception & Color](references/guide-visual-perception.md) | [Responsive & Zoom](references/guide-responsive-mobile.md)*
- **Contrast (SC 1.4.3, 1.4.11):** Text **MUST** have 4.5:1; UI components and meaningful graphics **MUST** have 3:1. Prioritize real **luminance difference** (light vs dark) beyond hue.
- **Alt Text (SC 1.1.1):** Every `<img>` carries an `alt` attribute — omitting it is always a violation. Informative and functional images **MUST** have a non-empty, functional description; the **empty value** (`alt=""`) is reserved for images a human confirmed as decorative — a decision, never a default. An `alt` deduced from a filename is fabricated evidence (see *Image Evidence*, Section 2).
- **Time-Based Media (SC 1.2.2, 1.2.5):** Prerecorded video carrying audio **MUST** have synchronized captions (SC 1.2.2); visual information the soundtrack does not convey **MUST** have an audio description (SC 1.2.5). Silent decorative media owes no captions — but "decorative" is a human-confirmed classification (see *Media Evidence*, Section 2), never the AI's default reading of a background asset.
- **Audio Control (SC 1.4.2):** Audio that plays automatically for more than 3 seconds **MUST** offer a mechanism to pause or stop it, or to control its volume independently of the system volume. Automatic sound masks the screen reader's own speech — the affected user's only channel of operation — so it is 🔴 CRITICAL, not a nuisance.
- **Text Spacing (SC 1.4.12):** Content **MUST** survive with no loss of information or function when the user applies line height 1.5×, spacing after paragraphs 2×, letter spacing 0.12× and word spacing 0.16×. Fixed height on a text container and `line-height` with `!important` are the two common causes of failure — use `min-height`.
- **Semantic Redundancy:** **MUST NOT** convey state using color alone. The use of **Icon + Text + Color** (e.g., 🔴 Error) is the mandatory standard.
- **Visual Patterns:** Charts and dashboards **MUST** use textures or distinct line styles to ensure differentiation without color. And a chart's text alternative is **the data**, not a description of the drawing: an informative chart ships an equivalent table or dataset. *Reference: [Charts & Data Visualization](references/guide-charts.md)*

### Operable
*References: [Buttons](references/guide-buttons.md) | [Modals](references/guide-modals.md) | [Navigation](references/guide-navigation.md) | [Tabs & Accordions](references/guide-tabs-accordion.md) | [Tree View & Hierarchy](references/guide-treeview.md) | [Carousels & Sliders](references/guide-carousels-sliders.md) | [Time-Based Media & Motion](references/guide-media.md) | [Drag & Drop](references/guide-drag-drop.md) | [Autocomplete](references/guide-autocomplete.md) | [Date Picker & Calendar](references/guide-datepicker.md) | [Interactive Maps](references/guide-maps.md) | [Infinite Scroll](references/guide-infinite-scroll.md)*
- **Keyboard (SC 2.1.1):** 100% of functionalities **MUST** be operable without a mouse. Avoid purely pointer-based listeners without keyboard event equivalents (`onKeyDown`).
- **Focus (SC 2.4.7, 2.4.11):** Focus **MUST** be visible, never entirely obscured by author content (e.g., sticky headers/footers), persistent, and never suppressed via CSS (`outline: none` without fallback is forbidden).
- **SPA Routing (Single Page Applications):** After client-side routing changes, focus **MUST** be managed and properly reset (e.g., sending focus to the top or an H1). Avoid lost focus on the screen.
- **Targets (SC 2.5.8):** Interactive elements MUST have a minimum size of **24x24 CSS pixels** — the WCAG 2.2 AA floor — except when an equivalent larger target exists, sufficient spacing prevents accidental activation, or the target sits inline in text.
  **House Rule†:** design to **44x44px** (48×48 under Shield), the ergonomic floor shared by Apple HIG and Material Design. Under Shield, 44×44 is normative (SC 2.5.5 AAA).
- **Label in Name (SC 2.5.3):** The accessible name of a control **MUST contain** the text visible on it, in the same order — voice-control users say what they read, and an `aria-label` that *replaces* the visible text makes the control unreachable by voice. Complement the visible text (`sr-only` suffix, or `aria-labelledby`); never substitute it. *(The axe rule for this ships disabled — [Governance §1.1](references/guide-governance.md).)*
- **Moving Content (SC 2.2.2):** Any movement, blinking, scrolling or auto-updating that **starts automatically, lasts more than 5 seconds and runs alongside other content MUST** have a mechanism to pause, stop or hide it. Looping background video, auto-scrolling marquees and self-advancing carousels are the common failures. This is a Level A requirement: it holds at every profile, Launchpad included, and being decorative is not an exemption.
- **Flashing (SC 2.3.1):** Content **MUST NOT** flash more than three times per second. 🔴 CRITICAL — a health risk, never a trade-off.
- **Timing Adjustable (SC 2.2.1):** Every time limit **MUST** be able to be turned off, adjusted to at least 10× the default, or extended — with at least a 20-second warning and at least 10 extensions through a simple action. A session that expires without warning is a Level A failure.
- **Motion (SC 2.3.3 AAA — enforced as House Rule† at every profile):** **MUST** respect `@media (prefers-reduced-motion)` — covering state animations, **autoplaying video and scroll-driven effects (parallax)**: under the preference, media MUST NOT autoplay and parallax degrades to a static composition. Build the reduced-motion path as the **default**, adding motion in the `no-preference` branch. *Reference: [Time-Based Media & Motion](references/guide-media.md)*

### Understandable
*References: [Forms & Errors](references/guide-forms.md) | [Cognitive Accessibility](references/guide-cognitive.md) | [Content & Microcopy](references/guide-content-interaction.md) | [Tables](references/guide-tables.md) | [Consent & Cookie Banners](references/guide-consent-banners.md) | [Toasts & Notifications](references/guide-toasts-notifications.md) | [Loading & Skeletons](references/guide-loading-skeleton.md) | [Generative & Conversational Interfaces](references/guide-generative-ui.md) | [Tooltips & Popovers](references/guide-tooltips-popovers.md)*
- **Labels (SC 1.3.1, 3.3.2):** Forms **MUST** have explicit labels connected via `id` and `for`, or via tag wrapping. Avoid reinventions that break native browser events.
- **Accessible Authentication (SC 3.3.8):** No login step **MUST** require a cognitive function test without an alternative. Blocking paste on password fields, omitting `autocomplete`, and requiring CAPTCHA transcription are the three recurring failures.
- **Redundant Entry (SC 3.3.7):** Information already provided in the same process **MUST** be auto-populated or offered for selection — except where re-entry is essential (password confirmation) or a security requirement.
- **Consistent Help (SC 3.2.6):** Where a help mechanism exists across multiple pages, it **MUST** appear in the same relative order on all of them.
- **Predictability:** Navigation behavior **MUST** be consistent and interactions must not cause unannounced sudden structural changes.
- **Dynamic Feedback (SC 4.1.3):** Dynamic events based on component state (such as Toasts, loading, and AJAX/fetch form successes) **MUST** be actively read or informed through `aria-live` regions or modern equivalents (`role="status"`, `role="alert"`).

### Robust
*References: [Governance & Compliance](references/guide-governance.md) | [Framework Mapping](references/guide-framework-mapping.md) | [Platform-Native Mapping](references/guide-platform-native.md)*
- **Semantic HTML:** **MUST** prefer native (HTML5) elements over custom ones.
- **Interoperability:** The code **MUST** be compatible with current assistive technologies (ISO 9241-171).

## 4. Visual Directives (Strict UI Criteria)
To ensure certification, these visual guidelines are non-negotiable:
- **Focus Indicator (House Rule† — inspired by SC 2.4.13 AAA, whose normative metric is an indicator area ≥ a 2 CSS px perimeter with 3:1 contrast between the focused/unfocused states):** The focus ring **MUST** have a minimum thickness of 2px and a contrast of at least 3:1 against the background. (The AA floor: focus visible — SC 2.4.7 — and not entirely obscured by author content — SC 2.4.11.)
- **Typography (House Rule† — WCAG defines no minimum font size at any level):** Text **MUST NOT** be smaller than the minimum font size of the active Compliance Profile (Section 0.1); 12px under the default Standard (AA).
    - *Density Exception:* In dense dashboards or secondary metadata (badges), **min 10px** is allowed with contrast raised to **7:1** as mitigation — a House Rule trade-off, not WCAG — documented in `EXCEPTIONS.md`.
- **Target Spacing & Hit Area:** See *Section 3 — Targets* for the minimum size rule and exceptions. In dense UIs (e.g., tables), if the visual size is smaller than 44px, the **hit area** (invisible clickable area) **MUST** be expanded via CSS/padding. Adjacent targets **SHOULD** have 8px of spacing.

## 5. Complex Component Protocol
When identifying a component with no mapped pattern (the §2.1 map has no matching row and the [APG](https://www.w3.org/WAI/ARIA/apg/) has no equivalent):
1. **Identify:** Look for a similar pattern in the [WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/).
2. **Validate:** Request human validation with a screen reader — the AI **MUST NOT** claim this test was performed, nor fabricate its results.
3. **Document:** Document expected behavior (keyboard and announcements).
4. **Scale:** Record the resolved pattern in `A11Y-DECISIONS.md` so future components reuse it instead of re-deriving it.

## 6. Anti-patterns (Do NOT do this)
- **Clickable Divs:** **MUST NOT** use `div` or `span` for click actions. Prefer native buttons. If forced to use them, manually replicate the behavior of a `<button>` (`role`, `tabindex="0"`, Enter and Space event listeners).
- **Leaked Focus Traps:** **MUST NOT** create modals without managing focus.

  When a modal is open:
  - Focus MUST move into the modal
  - Focus MUST be trapped within the modal
  - Focus MUST return to the triggering element when closed
  - Background content MUST NOT be interactive or reachable via keyboard

- **Placeholder Labels:** **MUST NOT** use `placeholder` as the sole form of label. Crucial instructions (like date formats) **MUST** be visible outside the field to prevent disappearance during filling.
- **ARIA Soup:** **MUST NOT** add ARIA where native HTML already provides the semantics — no ARIA is better than bad ARIA. Forbidden by default: redundant roles (`role="button"` on a `<button>`), `aria-label` duplicating visible text (drifts into an SC 2.5.3 failure), and static never-updated ARIA states (hardcoded `aria-expanded` — SC 4.1.2). ARIA is the fallback for gaps in native semantics ([First Rule of ARIA Use](https://www.w3.org/TR/using-aria/#rule1)), not a seasoning. *(WebAIM Million 2026: 133+ ARIA attributes per page, 6× 2019, more ARIA correlating with more errors.)*
- **Text over Video:** **MUST NOT** place text over moving media without a stable contrast layer. The text **MUST** sit on a scrim whose contrast is measured against that layer, in the composited worst case — the ratio over raw video changes frame by frame, and every automated checker passes it. "The video is dark enough" is not a measurement. *Measurement method: [Time-Based Media & Motion](references/guide-media.md)*
- **Orphaned ARIA Reference:** **MUST NOT** point `aria-controls`, `aria-labelledby`, `aria-describedby` or `aria-activedescendant` at an `id` absent from the rendered DOM. When a relationship attribute crosses a component boundary, the `id` **MUST** be generated on one side and passed explicitly to the other — never generated twice (`useId()` on both sides is the canonical failure, and it passes axe and Lighthouse). *Mechanism, tooling blind spots and the field case: [Framework Mapping](references/guide-framework-mapping.md)*
- **Nullified Alt:** **MUST NOT** apply `aria-hidden="true"` to an image carrying a non-empty `alt`, nor `role="presentation"` to an informative image. The image leaves the accessibility tree and the `alt` stops existing for the screen reader — while every checker keeps passing it, because the attribute is present. If the image is decorative, the markup is `alt=""` (a human decision, see *Image Evidence*); if it is informative, it cannot be hidden.
- **Accessibility Overlays:** **MUST NOT** propose an overlay widget — accessibility toolbar, "accessible mode" plugin, automatic remediation script — as the answer to a violation. An overlay does not fix the DOM that produced the barrier: it adds a layer that frequently conflicts with the assistive technology the person has already configured. This is the public position of the IAAP and the European Disability Forum, and the European Commission records that overlays do not guarantee compliance with European legislation. The fix belongs in the code that created the problem.
- **Content Held Hostage by JavaScript:** **MUST NOT** ship content whose visibility depends on a script having run. The common form is the entry animation — `opacity: 0` in CSS, made visible by script — which renders the page **empty** when the script fails, is blocked, or has not executed yet. No automated checker catches it, because in the checker's browser the script ran. The default rendered state **MUST** be the readable one: gate the animation on a pre-paint `no-js` class, or start visible and animate from there. *Depth: [Loading & Skeletons](references/guide-loading-skeleton.md)*
- **Focus Traps Nobody Asked For:** **MUST NOT** add `tabindex="0"` to a scrollable container that does not actually overflow — the axe rule `scrollable-region-focusable` is **conditional**, and applying it unconditionally litters the tab order with stops that lead nowhere. The related `eslint-plugin-jsx-a11y` conflict is resolved by configuration, never by disabling the rule. *Resolution: [Governance §1.1](references/guide-governance.md)*
- **Reinventing the Complex Wheel:** If you need complex components (Autocomplete Selects, [TreeViews](references/guide-treeview.md), [Datepickers](references/guide-datepicker.md), [Charts](references/guide-charts.md)), it is strongly recommended to use robust and accessible libraries (Headless UI) rather than building proprietary logic from scratch. The guides for these say what the library still owes you — adopting one satisfies the pattern, never the Definition of Done.

## 7. Verification Workflow (Definition of Done)
*Compliance must be verified through these steps (Refer to the [**Report Template**](templates/REPORT.md) for final QA details and the [**Governance Guide**](references/guide-governance.md) for audit readiness):*
- [ ] **Artifacts Present:** `REPORT.md` exists, is filled from the template, and is newer than the last interface change. If any deviation was accepted, `EXCEPTIONS.md` exists. All project artifacts are versioned, never gitignored.
- [ ] **Technical Check:** Clean code, testable via integrated linter (`eslint-plugin-jsx-a11y` or similar), and passing without critical violations through engines like `Axe`. Default configuration is not full coverage: axe ships valuable rules **disabled** (notably `label-content-name-mismatch`, SC 2.5.3), and the linter conflicts with axe on `no-noninteractive-tabindex` — both resolved in [Governance §1](references/guide-governance.md).
- [ ] **Tab Order:** `Tab` key path manually validated (Ensures absence of frontend dead-ends).
- [ ] **User Flow:** Dynamic interactions (SPAs) tested for feedback via `aria-live` in error and success scenarios without mouse use.
- [ ] **Zoom & Reflow:** Text resizes up to 200% without loss of content or function (SC 1.4.4); content reflows at 320 CSS px width — equivalent to 400% zoom on a 1280px viewport — without two-dimensional scrolling (SC 1.4.10). Preserve flexibility using relative density (Rem/Em).
- [ ] **Color & Perception:** No functional loss when losing the exclusive use of colors (vision deficiency simulators).
- [ ] **Beyond the Screen Reader:** every visible control can be activated **by speaking its visible label** (SC 2.5.3) — validated with the platform's voice control, or by reading each accessible name against its visible label. Voice, switch and full-keyboard access consume the same name and focus order the screen reader does, and each fails differently. *(Tools per platform: `templates/REPORT.md`.)*
- [ ] **Media & Motion:** every medium classified with the developer; captions human-reviewed; autoplay, pause and flashing rules verified; one pass with `prefers-reduced-motion: reduce` active. *(Full checklist: `templates/REPORT.md` §5.)*
- [ ] **Cognitive Load:** nothing remembered across screens, nothing retyped, help in a consistent place, paste allowed, text spacing survives, time limits adjustable. *(Full checklist: `templates/REPORT.md` §6.)*
- [ ] **Exceptions Audit:** `EXCEPTIONS.md` reviewed — every active entry has a risk owner, approver, tracking issue and expiry; no expired entries left unaddressed.
- [ ] **Independent Verification:** every checkpoint above that does not require a human was reproduced by a verifier that did not generate the code, and `REPORT.md` declares the level reached — **cross-agent**, **fresh-context**, or **self-reported ⚠️**. A self-reported report **MUST NOT** be closed as ✅ PASS (see *Independent Verification*, Section 2).

> **Agents without a browser.** Several checkpoints above require a person with a browser or assistive technology. A headless agent **MUST** still produce the `REPORT.md`, marking those items `[ ]` with the reason and naming who must run them. A partial, honest report is evidence; a missing report is not. The AI **MUST NOT** mark as verified any item whose evidence it cannot reproduce.
