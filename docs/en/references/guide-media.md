# Accessibility: Time-Based Media, Background Video & Motion

> Scope: video and audio, decorative/background media, parallax and scroll-driven motion, text over moving media, and the human-in-the-loop rule for captions and transcripts.

## 1. Classify before you embed

The removal test from the [Images guide](guide-images.md) applies unchanged: *"If I remove this media, what does the user lose?"*

| Answer | Class | What it owes |
| :--- | :--- | :--- |
| Loses information | **Informative** | captions (SC 1.2.2), transcript, audio description when the visuals carry what the soundtrack does not (SC 1.2.5) |
| Loses a function (plays a step, confirms an action) | **Functional** | an accessible name for the control **and** a non-media path to the same outcome |
| Loses nothing but atmosphere | **Decorative** | no captions — but still owes a pause mechanism (SC 2.2.2), silence (SC 1.4.2) and reduced-motion behavior |

**Decorative is not a synonym for background.** A hero video showing the product in use is informative *and* sits in the background. The class comes from what the media carries, not from where it sits.

## 2. Media Evidence — the three questions

The AI cannot perceive a media file. Multimodal input reads a pasted frame, not an `.mp4` in the repository, so the fallback of the Images guide ("I can see it, so I classify it") is unavailable here — the AI **asks, in the same turn**:

1. **Does it carry information or function**, or is it atmosphere? *(the classification of Section 1 — the developer's answer, not the AI's guess)*
2. **Does it have an audio track?** If yes: does it need to be audible, or can it ship muted?
3. **Do captions, a transcript or an audio description already exist?** If not, who produces them, and by when?

Captions and transcripts generated by the AI or by an automated service are **drafts for human review**, never the delivered alternative. An unreviewed machine caption is the `alt` deduced from a filename, in another medium: present, plausible, and wrong exactly where the content is hardest — names, jargon, numbers. The industry name for the result is *craptions*, and no automated checker flags them, because a `<track>` element is there.

## 3. Background video

The common case, and the one that fails most often. A silent decorative loop still owes three things:

### ✅ Correct

```html
<section class="hero">
  <!-- Confirmed decorative by the developer: carries no information. -->
  <video id="heroVideo" muted loop playsinline
         poster="hero-still.jpg"
         aria-hidden="true" tabindex="-1">
    <source src="hero.mp4" type="video/mp4">
  </video>
  <div class="hero__scrim"></div>

  <div class="hero__content">
    <h1>Ship accessible software</h1>
    <button type="button" id="heroMotionToggle">Pause background video</button>
  </div>
</section>
```

```js
// Autoplay is granted by script, never by the markup — so the preference can veto it
// before a single frame moves.
const video = document.getElementById('heroVideo');
const toggle = document.getElementById('heroMotionToggle');
const reduceMotion = window.matchMedia('(prefers-reduced-motion: reduce)');

const render = () => {
  toggle.textContent = video.paused ? 'Play background video' : 'Pause background video';
};
const respectPreference = () => {
  if (reduceMotion.matches) video.pause();   // the poster frame stays on screen
  else video.play();
  render();
};

toggle.addEventListener('click', () => { video.paused ? video.play() : video.pause(); render(); });
reduceMotion.addEventListener('change', respectPreference);
respectPreference();
```

- **`aria-hidden="true"` + `tabindex="-1"`** — the decorative video is removed from the accessibility tree and from the tab order. The pause button is **outside** it: a control inside an `aria-hidden` subtree is unreachable.
- **`muted`** — audio that starts on its own needs its own control (SC 1.4.2); shipping muted removes the problem instead of solving it.
- **`poster`** — the still frame is what reduced-motion users, slow connections and blocked autoplay all fall back to. Choose it deliberately: it becomes the real hero image.
- **The pause control is not optional.** A loop longer than 5 seconds is moving content under SC 2.2.2 — Level A. "It's just a background" is not an exemption in the criterion's text.

### ❌ Incorrect

```html
<video autoplay loop playsinline src="hero.mp4"></video>
```

Autoplays regardless of `prefers-reduced-motion`, offers no way to stop it, carries an unmuted audio track by default, and appears in the accessibility tree as an unnamed media element.

## 4. Text over media

The failure no tool catches. A headline over video has a contrast ratio that **changes frame by frame**, and every automated checker passes it: axe measures the text against the container's computed background — which is transparent — never against the pixels the user is looking at.

### ✅ Correct

```css
.hero__scrim {
  position: absolute;
  inset: 0;
  background: rgb(12 14 18 / 0.72);   /* the surface contrast is actually measured against */
}
.hero__content { position: relative; }   /* above the scrim */
```

Measure the text against the **composited worst case**: the lightest frame of the video seen through the scrim. If you cannot enumerate the frames, raise the scrim until the video no longer materially changes the result — an opaque band behind the text is a legitimate answer, and the only one that survives a video swap by the marketing team.

### ❌ Incorrect

- "The video is dark enough" — until the frame where it is not.
- A gradient tuned to the current cut, with no recorded decision. The next video breaks it silently.
- A `text-shadow` as the sole mitigation: it changes perceived legibility without changing the measurable ratio, so it is a fix for the reviewer, not for the user.

Record the accepted scrim value in `A11Y-DECISIONS.md`: it is a pattern-level decision, and the next hero will need it.

## 5. Parallax & scroll-driven motion

Scroll-driven translation is a vestibular trigger — nausea, dizziness and disorientation for users with vestibular disorders — and it is **not covered** by the pause button of Section 3, because the user never asked for the motion; scrolling did.

- Under `prefers-reduced-motion: reduce`, parallax **MUST** degrade to a static composition: layers stop translating, the section still reads.
- Build the reduced-motion path as the **default**, adding motion in the `no-preference` branch. Written the other way around, the fallback is the one nobody tests.

```css
.layer { transform: none; }                      /* default: no motion */

@media (prefers-reduced-motion: no-preference) {
  .layer { animation: parallax linear both; animation-timeline: scroll(); }
}
```

- Movement that starts by itself and outlives 5 seconds (auto-scrolling marquees, looping ticker text) is SC 2.2.2 again: it needs a stop, not just a preference query.

## 6. Informative & functional media

- **Captions (SC 1.2.2, A):** synchronized, via `<track kind="captions">`. They carry speech **and** the meaningful non-speech audio — `[door slams]`, `[alarm]`, speaker changes.
- **Transcript:** not required by name at AA, but it is the only alternative that works for deafblind users on a braille display, and the cheapest to produce. Link it next to the player, not three clicks away.
- **Audio description (SC 1.2.5, AA):** required when the picture carries information the soundtrack does not — a chart appearing on screen, on-screen text nobody reads aloud. The cheap fix is upstream: script the narration so it says what the screen shows, and the description becomes unnecessary.
- **Controls:** prefer the native `controls` attribute. A custom player is a Complex Component (Section 5 of the core file) — keyboard operable end to end, every control a real `<button>` with a name, state announced.
- **Third-party embeds (YouTube, Vimeo, Loom):** the embed does not transfer the obligation. Verify that captions exist on the hosted asset and that the `<iframe>` carries a `title`. Auto-generated captions are a draft, exactly as in Section 2.

## Tip for AI:

Before embedding any `<video>` or `<audio>`, ask yourself the question you cannot answer alone: *"Does this carry information — and who is going to write the captions?"* You can perceive an image. You cannot perceive a video. Ask.
